INTRODUCTION
============

L'application que vous allez enrichir s'appelle "Resource Discovery Platform".
Son rôle est d'aider des administrateurs à découvrir, valider et gérer des
ressources d'aide contre le cyberharcèlement (associations, numéros d'urgence,
procédures de signalement...) dans plusieurs langues et plusieurs pays.

Concrètement, un administrateur peut demander à l'application :
"Trouve-moi des ressources officielles contre le cyberharcèlement en Allemagne,
en langue allemande." L'application interroge alors un modèle d'intelligence
artificielle (LLM — Large Language Model) qui retourne une liste de ressources
pertinentes. Ces ressources sont ensuite validées et stockées pour alimenter
un chatbot d'assistance aux victimes.

L'application est composée de deux parties :
  - un backend Python (FastAPI) qui gère la logique métier et les données
  - un frontend React (TypeScript) qui fournit l'interface d'administration


LE PROBLÈME ACTUEL
==================

Pour fonctionner, l'application a besoin de savoir : pour chaque langue
supportée, quels sont les pays associés ?

Exemple :
  - Langue "FR" (Français) → France, Belgique, Suisse, Canada, Luxembourg
  - Langue "DE" (Deutsch)  → Allemagne, Autriche, Suisse
  - Langue "EN" (English)  → Royaume-Uni, États-Unis, Australie...

Ces informations existent côté backend dans un fichier Python (constants.py)
bien structuré et exposé via une API. Mais côté frontend, dans le formulaire
de découverte (DiscoveryForm.tsx), cette liste est recopiée manuellement
sous forme d'une constante en dur :

    const LANGUAGES = [
        { code: 'FR', name: 'Français', countries: ['France', 'Belgique', ...] },
        { code: 'EN', name: 'English',  countries: ['UK', 'USA', ...] },
        ...
    ]

Ce tableau pose plusieurs problèmes :
  1. Il est désynchronisé du backend (ex: "UK" au lieu de "United Kingdom")
  2. Il est incomplet (la langue "IT" — Italiano — est absente)
  3. Si un administrateur veut ajouter un pays, il doit modifier le code source
     du frontend et redéployer l'application

La solution est de donner aux administrateurs une interface pour gérer eux-mêmes
cette configuration, sans toucher au code.


L'OBJECTIF DU TP
================

Vous allez implémenter un CRUD complet pour la gestion des langues et des pays.

CRUD est l'acronyme des quatre opérations fondamentales sur des données :

  C — Create  : ajouter une nouvelle langue ou un nouveau pays
  R — Read    : afficher la liste des langues et de leurs pays
  U — Update  : modifier le nom d'une langue ou d'un pays existant
  D — Delete  : supprimer une langue ou un pays

En pratique, cela se traduit par :

  Read    → GET    /admin/config/countries-languages        (déjà existant)
  Create  → POST   /admin/config/countries-languages        (à implémenter)
  Update  → PUT    /admin/config/countries-languages/{code} (à implémenter)
  Delete  → DELETE /admin/config/countries-languages/{code} (à implémenter)

Côté frontend, vous allez créer une page "Configuration" accessible depuis
le menu principal, avec :
  - un tableau listant les langues et leurs pays (Read)
  - un formulaire pour ajouter une langue avec ses pays (Create)
  - la possibilité de modifier une langue existante (Update)
  - un bouton de suppression avec confirmation (Delete)

Le formulaire de découverte (DiscoveryForm.tsx) devra ensuite utiliser
dynamiquement cette configuration au lieu de la constante codée en dur.

PARTIE 1 — LES APIS BACKEND DISPONIBLES (référence)
============================================================

Le backend est fourni et démarré. Vous n'avez pas à le modifier.
Il expose les endpoints suivants pour la gestion des langues et pays.

L'URL de base est : http://localhost:8000
Le header d'authentification requis pour tous les appels :
  Authorization: Bearer admin-token-2024


--- LIRE LA CONFIGURATION ---

  GET /admin/config/countries-languages

    Retourne la liste complète de toutes les langues et leurs pays.

    Réponse :
    {
      "success": true,
      "languages": {
        "FR": {
          "countries": [
            { "country_name": "France",   "country_code": "FR", "flag": "🇫🇷" },
            { "country_name": "Belgique", "country_code": "BE", "flag": "🇧🇪" }
          ]
        },
        "DE": { "countries": [...] }
      },
      "total_languages": 6,
      "total_countries": 28
    }

  GET /admin/config/countries-languages/{code}

    Retourne la configuration d'une seule langue.
    Exemple : GET /admin/config/countries-languages/FR

    Réponse :
    {
      "success": true,
      "language": "FR",
      "config": { "countries": [...] }
    }


--- MODIFIER UNE LANGUE ---

  PUT /admin/config/countries-languages/{code}

    Remplace entièrement la configuration d'une langue.
    Exemple : PUT /admin/config/countries-languages/FR

    Corps de la requête (JSON) :
    {
      "code": "FR",
      "countries": [
        { "country_name": "France",  "country_code": "FR", "flag": "🇫🇷" },
        { "country_name": "Maroc",   "country_code": "MA", "flag": "🇲🇦" }
      ]
    }


--- AJOUTER UN PAYS À UNE LANGUE ---

  POST /admin/config/countries-languages/{code}/countries

    Ajoute un pays à une langue existante sans toucher aux autres.
    Exemple : POST /admin/config/countries-languages/FR/countries

    Corps de la requête (JSON) :
    {
      "country_name": "Maroc",
      "country_code": "MA",
      "flag": "🇲🇦"
    }


--- SUPPRIMER UN PAYS ---

  DELETE /admin/config/countries-languages/{code}/countries/{country_code}

    Supprime un pays d'une langue.
    Exemple : DELETE /admin/config/countries-languages/FR/countries/MA


--- SUPPRIMER UNE LANGUE ENTIÈRE ---

  DELETE /admin/config/countries-languages/{code}

    Supprime une langue et tous ses pays.
    Exemple : DELETE /admin/config/countries-languages/IT


NOTE : Vous pouvez tester ces endpoints directement dans votre navigateur
ou avec l'outil curl avant de les appeler depuis React.
Exemple curl pour lire la config :

  curl -H "Authorization: Bearer admin-token-2024" \
       http://localhost:8000/admin/config/countries-languages

PARTIE 2 — TYPER LES DONNÉES EN TYPESCRIPT
Fichier : frontend/src/services/api.ts
============================================================

Avant d'appeler une API depuis React, il faut décrire en TypeScript la forme
des données que l'on va recevoir. C'est le rôle des interfaces.

Une interface TypeScript ressemble à un contrat : elle dit à votre code
"je m'engage à ce que cet objet ait exactement ces propriétés et ces types".
Si le backend envoie autre chose, TypeScript vous le signalera.


ÉTAPE 2.1 — Créer les interfaces
---------------------------------

Regardez la réponse JSON du GET /admin/config/countries-languages.
On y distingue trois niveaux imbriqués. Chaque niveau mérite sa propre
interface, pour pouvoir les réutiliser indépendamment plus tard.

Niveau 1 — Un pays :
    { "country_name": "France", "country_code": "FR", "flag": "🇫🇷" }

    export interface CountryConfig {
        country_name: string
        country_code: string
        flag: string
    }

    Attention : les noms de propriétés doivent correspondre exactement
    à ce que le backend envoie. "flag" et non "country_flag".

Niveau 2 — La configuration d'une langue :
    { "countries": [ {...}, {...} ] }

    export interface LanguageConfig {
        countries: CountryConfig[]
    }

    CountryConfig[] se lit : "un tableau d'objets de type CountryConfig".

Niveau 3 — La réponse complète de l'API :
    { "success": true, "languages": { "FR": {...}, "DE": {...} } }

    export interface ConfigResponse {
        success: boolean
        languages: { [languageCode: string]: LanguageConfig }
    }

    { [languageCode: string]: LanguageConfig } est appelé une "index signature".
    Elle exprime : "les clés sont des strings quelconques (FR, DE, EN...),
    et chaque valeur est de type LanguageConfig". On l'utilise quand les clés
    ne sont pas connues à l'avance.

Ajoutez ces trois interfaces dans api.ts, à la suite des interfaces existantes.


ÉTAPE 2.2 — Créer la fonction de lecture (Read)
-------------------------------------------------

Toujours dans api.ts, ajoutez la fonction qui appelle le backend.
Inspirez-vous des fonctions existantes dans le fichier (fetchResources,
getResourceStats...) — elles suivent toutes le même schéma :

    export async function fetchLanguagesConfig(): Promise<ConfigResponse> {
        const response = await fetch(
            `${API_BASE_URL}/admin/config/countries-languages`,
            { headers: { 'Authorization': AUTH_TOKEN } }
        )
        if (!response.ok) {
            throw new Error(`Erreur API: ${response.status}`)
        }
        return response.json()
    }

Points importants :
  - Le type de retour Promise<ConfigResponse> indique ce que la fonction
    retourne de manière asynchrone.
  - response.json() retourne directement l'objet — pas besoin d'extraire
    une propriété comme dans fetchResources qui fait data.sources.
    La différence : ici la réponse JSON EST le ConfigResponse, alors que
    fetchResources reçoit { sources: [...], total: 5 } et n'en veut que
    le tableau sources.

À ce stade, testez que TypeScript ne signale aucune erreur (aucun trait
rouge dans l'éditeur) avant de passer à la suite.

ÉTAPE 3.1 — Créer le hook useLanguagesConfig
---------------------------------------------

Un "hook" React est une fonction dont le nom commence par "use" et qui
encapsule une logique réutilisable avec de l'état. On crée un hook dédié
plutôt que de mettre la logique directement dans le composant, parce que
cette configuration sera utilisée dans deux endroits différents :
  - DiscoveryForm    (lire les langues/pays pour le formulaire)
  - ConfigPage       (lire + modifier + supprimer en partie 4)

Créez le fichier : frontend/src/hooks/useLanguagesConfig.ts

Ce hook doit gérer trois états :
  - config  : ConfigResponse | null   → null pendant le chargement
  - loading : boolean                 → true pendant le chargement
  - error   : string | null           → message d'erreur si échec

Structure à compléter :

    import { useState, useEffect } from 'react'
    import { fetchLanguagesConfig, type ConfigResponse } from '../services/api'

    export function useLanguagesConfig() {
        const [config, setConfig]   = useState<ConfigResponse | null>(null)
        const [loading, setLoading] = useState<boolean>(true)
        const [error, setError]     = useState<string | null>(null)

        useEffect(() => {
            fetchLanguagesConfig()
                .then(data => {
                    setConfig(data)
                })
                .catch(err => {
                    setError(err.message)
                })
                .finally(() => {
                    setLoading(false)
                })
        }, [])   // ← tableau vide = exécuté une seule fois au montage

        return { config, loading, error }
    }

Le tableau vide [] passé à useEffect est essentiel : sans lui, le hook
rappellerait l'API à chaque re-render du composant.

.finally() est exécuté dans tous les cas (succès ou erreur) — c'est
l'endroit idéal pour désactiver le loading.


ÉTAPE 3.2 — Modifier DiscoveryForm pour utiliser le hook
----------------------------------------------------------

Ouvrez frontend/src/components/features/DiscoveryForm.tsx.

Vous verrez en haut du fichier la constante à supprimer :

        { code: 'FR', name: 'Français', countries: ['France', 'Belgique', ...] },

Modifications à effectuer :

1. Supprimez entièrement la constante LANGUAGES.

2. En haut du composant, appelez le hook :

3. Remplacez la ligne qui cherche la langue courante :

    const currentLanguage = LANGUAGES.find(l => l.code === language)

    // Après (avec la config dynamique) :
    const currentCountries = config?.languages[language]?.countries ?? []

        <option key={lang.code} value={lang.code}>{lang.name}</option>

    de langue ("FR", "DE", "EN"...).

    // Après :
    {currentCountries.map(country => (
        <label key={country.country_code} ...>
            {country.flag} {country.country_name}
        </label>

    Notez : on itère maintenant sur des objets CountryConfig complets,
    on affiche country.country_name (et non plus une simple chaîne),
    et c'est aussi country.country_name qui sera stocké dans
    selectedCountries et envoyé au backend — cohérence garantie.

6. Gérez les états de chargement et d'erreur dans le JSX :

    if (loading) return <p>Chargement de la configuration...</p>
    if (error)   return <p>Erreur : {error}</p>

    Ces lignes se placent juste avant le return du formulaire.

--- Ajouter un pays à une langue ---

    export async function addCountryToLanguage(
        languageCode: string,
        country: CountryConfig
    ): Promise<void> {
        const response = await fetch(
            `${API_BASE_URL}/admin/config/countries-languages/${languageCode}/countries`,
            {

                    'Content-Type': 'application/json',
                    'Authorization': AUTH_TOKEN,

        )
        if (!response.ok) throw new Error(`Erreur API: ${response.status}`)
    }

--- Supprimer un pays d'une langue ---

    export async function removeCountryFromLanguage(
        languageCode: string,
        countryCode: string
    ): Promise<void> {
        const response = await fetch(
            `${API_BASE_URL}/admin/config/countries-languages/${languageCode}/countries/${countryCode}`,
            {
                method: 'DELETE',
                headers: { 'Authorization': AUTH_TOKEN },
            }
        )
        if (!response.ok) throw new Error(`Erreur API: ${response.status}`)
    }

--- Supprimer une langue entière ---

    export async function deleteLanguage(languageCode: string): Promise<void> {
        const response = await fetch(
            `${API_BASE_URL}/admin/config/countries-languages/${languageCode}`,
            {
                method: 'DELETE',
                headers: { 'Authorization': AUTH_TOKEN },
            }
        )
        if (!response.ok) throw new Error(`Erreur API: ${response.status}`)
    }

--- Remplacer tous les pays d'une langue ---

    export async function updateLanguage(
        languageCode: string,
        config: LanguageConfig & { code: string }
    ): Promise<void> {
        const response = await fetch(
            `${API_BASE_URL}/admin/config/countries-languages/${languageCode}`,
            {
                method: 'PUT',
                headers: {
                    'Content-Type': 'application/json',
                    'Authorization': AUTH_TOKEN,
                },
                body: JSON.stringify(config),
            }
        )
        if (!response.ok) throw new Error(`Erreur API: ${response.status}`)
    }

Note : ces fonctions retournent Promise<void> car le backend confirme
le succès avec un code HTTP 200 — on n'a pas besoin de lire le corps
de la réponse.


ÉTAPE 4.2 — Enrichir useLanguagesConfig avec les mutations
-----------------------------------------------------------

Le hook créé en partie 3 expose seulement config/loading/error.
Il faut lui ajouter des fonctions pour modifier les données.

L'idée clé : après chaque modification (ajout, suppression), on rappelle
fetchLanguagesConfig() pour rafraîchir l'affichage. C'est le pattern
"refetch after mutation" — on relit la source de vérité après chaque write.

Enrichissez useLanguagesConfig.ts :

    import {
        fetchLanguagesConfig,
        addCountryToLanguage,
        removeCountryFromLanguage,
        deleteLanguage,
        type ConfigResponse,
        type CountryConfig,
    } from '../services/api'

    export function useLanguagesConfig() {
        const [config, setConfig]   = useState<ConfigResponse | null>(null)
        const [loading, setLoading] = useState<boolean>(true)
        const [error, setError]     = useState<string | null>(null)

        const loadConfig = () => {
            fetchLanguagesConfig()
                .then(data => setConfig(data))
                .catch(err => setError(err.message))
                .finally(() => setLoading(false))
        }

        useEffect(() => { loadConfig() }, [])

        const addCountry = async (languageCode: string, country: CountryConfig) => {
            await addCountryToLanguage(languageCode, country)
            loadConfig()   // rafraîchit après écriture
        }

        const removeCountry = async (languageCode: string, countryCode: string) => {
            await removeCountryFromLanguage(languageCode, countryCode)
            loadConfig()
        }

        const removeLang = async (languageCode: string) => {
            await deleteLanguage(languageCode)
            loadConfig()
        }

        return { config, loading, error, addCountry, removeCountry, removeLang }
    }

La fonction loadConfig() est extraite pour être appelée à la fois au
montage (via useEffect) et après chaque mutation — sans dupliquer le code.
